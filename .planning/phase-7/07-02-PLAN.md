<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-supplied dateFrom / dateTo / auditFlagFilter → this.$route.query | Filter values are user-typed (date inputs) or user-toggled (checkboxes); they round-trip through $router.replace into the URL. No store mutation, no backend round-trip. |
| auditlog / buildlog Vuex state → filteredAudit / filteredBuilds predicates | Read-only consumption; this plan adds no new state writes. |
| Per-row expandedBuilds[] → DOM rendering | Component-local list of expanded build keys; affects only client-side rendering of the build's own log text. No backend call, no store mutation. |
| logFull(item) interpolation → <pre> textContent | item.log content (backend-supplied build output) is rendered as text via {{ ... }}, not v-html — Vue auto-escapes HTML, so even if the backend returns log lines containing `<script>` they will not execute. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02-01 | Tampering | $route.query round-trip for filter state | accept | Filter values land in this.$route.query and are re-hydrated on reload by Wave 1's created() hook.
