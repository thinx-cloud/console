## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query string → History.vue filter state | this.$route.query.{from,to,flags} flows into dateFrom / dateTo / auditFlagFilter via the created() hydration block — values originate from the user-controllable URL bar |
| History.vue filter state → DOM rendering | dateFrom / dateTo / auditFlagFilter flow through filteredAudit / filteredBuilds into the existing v-for that renders b-list-group-items |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01-01 | Tampering | created() hydration of dateFrom/dateTo from $route.query | accept | The values feed `new Date(...).getTime()`. Invalid strings produce NaN, which the `Number.isFinite(t)` guard converts into an "include this item" decision. No XSS path exists — the strings are never injected into the DOM as raw HTML; they are only used as Date constructor inputs and as v-model values on inputs (Wave 2). Worst case: a malicious URL silently disables one side of the date range. |
| T-07-01-02 | Tampering | created() hydration of auditFlagFilter from $route.query.flags | accept | A crafted ?flags=foo,bar,danger value populates auditFlagFilter with arbitrary strings. The flag predicate uses `Array.includes(...)` against item.flags — non-matching values simply fail to include any items, which is a benign UX outcome (the user can re-check the boxes in Wave 2's UI). No injection vector. |
| T-07-01-03 | Information Disclosure | HIST-02 route names exposed in URL bar | accept | /app/history/audit and /app/history/builds are not sensitive paths — they replace the existing /app/history with the same access controls (the AppLayout parent route already gates auth). No new data is exposed. |
| T-07-01-04 | Denial of Service | filteredAudit / filteredBuilds re-evaluation on every keystroke / date change | accept | Vue's reactivity already memoizes computeds based on their reactive dependencies. The added predicates are O(n) over auditLogs / buildLogs (which are typically a few hundred items max for a single owner). No new performance hazard versus the current text-only filter. |
| T-07-01-05 | Elevation of Privilege | parent route name dropped — risk of breaking other navigation | mitigate | grep the codebase for any `name: 'History'` references in router.push / router-link calls before merging. The Sidebar uses path-based navigation (`{ path: '/app/history' }`), not name-based. If any name-based callers exist, the wave verification step catches them via the manual smoke check (which navigates from the sidebar and via direct URL entry). |
| T-07-01-SC | Tampering | npm supply chain | accept | This plan installs NO new npm packages. All date arithmetic uses the platform Date constructor. |
</threat_model>
