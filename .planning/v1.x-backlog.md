## ADMIN-search: Admin user-list search/filter

**Source:** Phase 10 live UAT acceptance note (2026-05-26 — `.planning/phase-10/10-HUMAN-UAT.md` §Acceptance note)
**Estimate:** S
**Status:** Captured

Today `/app/admin/users` is paginated only. For fleets with many users, finding a specific account requires clicking through pages. Add a search / filter input on `AdminUsers.vue` that filters on `username` and `email`.

**Sketch:**
- Backend: extend `GET /api/v2/admin/users` in `lib/router.admin.js` with a `q=` query param. CouchDB Mango query is the cleanest given the docs are already in `managed_users`.
- Frontend: debounced search input in `AdminUsers.vue` toolbar; on input, refetch with `q=` param and reset pagination to page 1.
- Decision needed: case-insensitive substring (better UX) vs prefix-only (cheaper query). Substring probably, bounded by pagination so we don't ship 10k matches.

**Dependencies:** None. Self-contained.

## AUTH-bearer-null: Vue console sends `Bearer null` on logged-out requests

**Source:** Frontend half of the parent monorepo's Phase 1 / AUTH-API-01 root-cause investigation (2026-05-26). See parent `.planning/milestones/v1.0-phases/01-auth-api-password-reset/01-SUMMARY.md` §"Root cause" + §"Fix philosophy".
**Estimate:** XS
**Status:** Captured (harmless after parent backend fix; hygiene cleanup only)

`vue/src/core/api.js:53-57` unconditionally serializes `Authorization: 'Bearer ' + this.refreshToken` on every outbound request. When the user is logged out, `this.refreshToken === null`, so the literal string `"Bearer null"` ships as the auth header on every public-route call (e.g. `POST /api/v2/password/reset`).

This was the frontend half of the G8 403 regression. The parent monorepo's Phase 1 shipped a class-fix Bearer-null guard at `lib/router.js:103` (parent commit `622aa01`) so the malformed header now falls through to the cookie/no-auth path — the Vue side is no longer load-bearing for correctness. The cleanup is the right hygiene fix: don't send an `Authorization` header at all when there's no token to send.

**Sketch:**
- In `vue/src/core/api.js#composeOptions` (or wherever the header is currently set), gate the `Authorization` line on `this.refreshToken != null` (covers both `null` and `undefined`)
- Consider the symmetric check on the access-token branch
- Behavior unchanged for authenticated requests; logged-out requests should ship with NO `Authorization` header (verify in Network tab on a logged-out `/password/reset` POST)

**Dependencies:** None — purely client-side cleanup. Safe under the parent's backend guard.

## CY-loginargs: `cy.login(user, pass)` ignores its arguments

**Source:** Surfaced by background agent during Phase 10 Wave 3 `cy.loginAsAdmin()` work — `vue/cypress/support/commands.ts:43`
**Estimate:** XS
**Status:** Captured (latent bug)

`cy.login` is declared with `(user, password)` parameters but always reads `fixtures.username` / `fixtures.password`. Harmless today because all 7 non-admin specs rely on the current fixture-only behavior — but any future test that calls `cy.login('alice', 'secret')` would silently log in as the leaked test fixture instead.

**Fix options:**
- Honor the params when provided, default to fixture when absent (semantic-preserving for existing 7 specs; small TS change)
- Rename the parameterized variant to `cy.loginAs(user, pass)`, keep `cy.login()` as the fixture-only shortcut (cleaner separation of intent; matches the new `cy.loginAsAdmin()` pattern)

The second option matches the existing `cy.loginAsAdmin()` naming and makes intent unambiguous at every call site.

**Dependencies:** None — purely test-side cleanup.
