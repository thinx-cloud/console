<objective>
Add a self-cancelling session-expiry timer (AUTH-03) that fires `auth/clearSession` and redirects to `#/login` when the access JWT's `exp` claim is reached. Wire the timer in at every entry point that writes a fresh access token (login-success, Login.vue rehydrate, App.vue cold-boot rehydrate) and refactor Header.vue's logout to dispatch the same `clearSession` action so manual logout and timer-triggered logout share one code path. Optionally add a belt-and-suspenders pre-request `exp` check in `core/api.js` for the laptop-sleep edge case where the in-memory `setTimeout` never fired.

Purpose: today the Vue router stays "logged in" after the JWT expires (`localStorage.authenticated` outlives the session cookie) and silent 403s pile up. The fix is a JS-side setTimeout armed at every token-write boundary, plus a single `clearSession` action that owns the four-op localStorage + state wipe (currently inlined in `Header.vue#logout`). The timer self-cancels on logout / re-login / manual reload — the module-private `expiryTimerId` is cleared and replaced at every call.

Note on routing from the store: Vuex actions have no `$router` reference. The app uses hash-mode routing (`Routes.js:27`), so `window.location.hash = '#/login'` is the locked redirect mechanism inside the store. Manual logout in `Header.vue` keeps `this.$router.push('/login')` because the component has a router instance — that's correct and intentional.

Note on the setTimeout clamp: `setTimeout` clamps delays to ~24.8 days (2^31 - 1 ms). Access tokens expire in 1 h and refresh tokens in 1 week — both well under the limit. No chained-timer scheme is needed.

Output: `vue/src/store/auth.js` gains two actions and one module-private variable; `Login.vue`, `App.vue`, and `Header.vue` are wired to the new action surface; `api.js` optionally gains a pre-request `exp` check. No new npm packages. No changes to existing actions / mutations / getters.
</objective>

      scheduleExpiry({ dispatch }, token) {
        if (expiryTimerId) {
          clearTimeout(expiryTimerId);
          expiryTimerId = null;
        }
        if (!token) return;
        try {
          const decoded = VueJwtDecode.decode(token);
          if (!decoded || typeof decoded.exp !== 'number') return;
          const msUntilExpiry = decoded.exp * 1000 - Date.now();
          if (msUntilExpiry <= 0) {
            dispatch('clearSession');
            if (typeof window !== 'undefined') window.location.hash = '#/login';
            return;
          }
          expiryTimerId = setTimeout(() => {
            dispatch('clearSession');
            if (typeof window !== 'undefined') window.location.hash = '#/login';
          }, msUntilExpiry);
        } catch (e) {
          // Bad token shape — let the normal auth flow (next API call → 401) handle it.
          // No need to dispatch clearSession here; the user has not yet logged in or the rehydrate
          // path is about to bail anyway.
          // eslint-disable-next-line no-console
          console.warn('[auth] scheduleExpiry decode failed', e);
        }
      },
